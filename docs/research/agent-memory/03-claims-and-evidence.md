# 03 · 论断—证据对照与可复现性评估

> 本页把原文的每一条**可检验论断**单独列出，标注证据形态、证据强度与本文的采信结论，并列出**原文未给出**、因此不能推导的信息。
> 目的是让后续设计决策能引用"哪条证据支持"，而不是引用"某篇文章说"。

## 1. 证据分级口径

| 等级 | 含义 |
| --- | --- |
| **E1 单案例 / 单 run** | 有具体细节与因果链，但 n=1，无重复、无统计 |
| **E2 同 benchmark 内对照** | 有 A/B 对照或跨模型对照，方向明确，但样本量/置信区间未公布 |
| **E3 规模曲线** | 有随规模增长的连续测量（如 2→128 sessions） |
| **E4 产品化事实** | 已在官方产品/文档中固化的机制与限制（可独立核验） |
| **E5 外部实践** | 原文链接的第三方模式文档，非 Anthropic 评测 |

## 3. 原文未给出、因此不可推导的信息

### 3.1 统计与方法学缺口

| 缺口 | 影响 |
| --- | --- |
| **无样本量、无重复次数、无置信区间** | 除 13%→48% 的规模曲线外，所有对照都不能当效应量使用 |
| **Pokémon 与 Mt. Moon 均为 n=1** | 不能推断"减少 98% 记忆文件会带来 4 倍进度"这类定量结论 |
| **CL-Bench 增益仅以图形呈现** | 正文只有"几乎翻倍"（Sonnet 4.6 引导后）一个数字 |
| **无随机种子 / 温度 / 采样次数说明** | 无法判断结果的稳定性与可复现性 |
| **评测集规模偏小** | Stainless 25 题、LAB 24 题、部分任务单文档——结论的方差可能很大 |

### 3.2 数字口径的不一致（引用时必须小心）

原文在同一段给出：**仅 wiki 48%**、**仅 search 53%**、**search + wiki 54%→61%**。

- 48% 明确是"问题只用 wiki 回答"的最佳分；
- 53% 是"只有 search 工具"时的聚合分；
- 61% 是"search + wiki 且 wiki 增长"时的聚合分。

**因此不能得出"wiki 让 53% 变成 61%"之外的推论**（例如不能说"wiki 带来 +8%"是纯粹表示层的贡献——它同时包含规模增长效应）。引用时必须**带口径**。

### 3.3 缺失的成本与运维信息

| 缺口 | 为什么重要 |
| --- | --- |
| **dreaming 的单位成本模型** | 128 个 session 的算力/时间未给出；无法判断"多久 dream 一次" |
| **记忆规模增长曲线与延迟** | 只有"每题省 20k tokens"，没有检索延迟、索引规模上限 |
| **遗忘/删除策略** | 除 lint 与 merge 外，**没有**说明过期记忆如何被清除或失效 |
| **多用户/多租户隔离** | 除"store 按所有者拆分"外无具体隔离或越权实验 |
| **注入攻击的实际测试** | 产品文档给出风险与建议，但**原文没有**对抗性实验 |
| **失败模式统计** | 只有零星案例（Sonnet 3.7 放弃循环、坏链），无失败率 |

### 3.4 结论的适用范围（本文判断）

| 结论 | 可信外推范围 | 不宜外推的场景 |
| --- | --- | --- |
| 少而精优于全量记录 | 长周期、状态高频变化的任务（游戏、交互式环境） | 合规/审计型任务可能需要全量留存 |
| 让模型自判 salience | 前沿模型的开放任务 | 强监管、必须固定记录项的场景；弱模型需要显式引导 |
| wiki 表示提升问答 | 大语料、跨文档综合问答、问题反复出现 | 小语料、单文档问答（无收益）、高频变更语料（维护成本高） |
| 顶层注入保持小 | 通用 agent | 每个 session 都必须无条件遵守的少量硬约束（此时应走系统提示/工具约束，而不是靠"记忆注入"） |
| dreaming 纠错 | 有 transcript 可回溯的系统 | 无法保留原始 transcript（已被清理/无权限）的系统 |

## 4. 可复现性检查清单

要在自己的系统上复现或否定原文的结论，最少需要：

| 项 | 要求 |
| --- | --- |
| **baseline 组** | ① 无记忆；② 仅检索；③ 记忆 + 检索（原文的对照结构） |
| **session 隔离** | 每个任务用**全新 session**，唯一跨 session 的是 memory（原文 CL-Bench 的做法） |
| **重复次数** | 每个配置**多次运行**并报告分布（原文缺失，是复现时最该补的） |
| **成本记账** | token（读写/检索/整理）、墙钟、整理算力；分开统计 |
| **错误传播测量** | 注入错误条目 → 测量其被读/被采信/被下游使用的比例 |
| **记忆体积监控** | 文件数、总字节、`表示/语料` 比值随时间的曲线 |
| **种子与版本** | 固定模型版本、温度、采样数；记录整理任务使用的模型 |
| **人工抽检** | 抽样若干记忆条目核对事实正确性（原文没有做这一层报告） |

## 5. 结论

- 原文的**概念框架与产品化机制（C1–C3、C21–C30）证据等级最高**，可以直接作为设计输入；
- 原文的**表示层收益（C11–C14）是唯一有规模曲线的证据**，可信度最高，但结论受任务形态强烈约束；
- 原文的 **salience 与 dreaming 案例（C4、C9）方向可信、量级不可信**，应当作为"设计假设 + 自测项"；
- 原文**没有给出成本模型、统计显著性与失败率**，任何"照抄即可"的期待都应转为**先建评测再迭代**（与 RSI 调研中的同类结论一致：先建评估平面，再建改进引擎）。
