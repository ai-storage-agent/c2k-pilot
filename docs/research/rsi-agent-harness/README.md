# RSI Agent Harness 参考架构调研

> **调研对象：** 当今前沿 agent system 研究，聚焦递归自我改进（Recursive Self-Improvement, RSI）方向。
> **交付物：** 一套可实现的 RSI agent harness 参考架构。
> **调研日期：** 2026-11-04。**语言：** 中文。

## 这是什么

这份调研把 2024–2026 年间关于"agent 改进自己"的研究——从 Gödel machine、Darwin Gödel Machine、ADAS 到 2026 年爆发的 harness engineering 文献——抽象成一套**分层、可施工的参考架构**，并诚实标注哪些部分有可靠证据、哪些仍是开放问题。

它回答三个问题：

1. **今天这个领域是什么样？**（[01 全景](01-landscape.md)）
2. **"递归自我改进"的严格含义是什么，它的理论边界在哪里？**（[02 概念与形式化](02-rsi-foundations.md)）
3. **一个 RSI agent harness 应该长什么样、怎么实现、有哪些坑？**（[03](03-harness-anatomy.md) – [07](07-implementation-landscape.md)）

## 一页结论

**参考架构 = 六职责执行 harness + 六类可修改制品 + S1–S4/RI 改进循环 + 三层证据评估 + 独立治理平面**，由三条不变量约束：

1. **harness 是一等可修改对象**——否则无从改进；
2. **改进必须触达 `B`/`U` 才叫 RSI**——否则只是一次性优化；
3. **自我修改必须可验证、可回滚、可审计**——否则不可控。

最容易被低估的两个发现：

- **验证者本身会退化，而下游分数看不出来。** 一个坍缩成"恒通过"的评分器，训练效果与真评分器一样好；因此验证器必须用与被改进系统分数无关的标准选择和审计。
- **约束会被"遮罩式"地静默侵蚀。** 任务成功率的提升可以掩盖冗余守护的流失，而这种流失在复用更弱模型时才暴露为危害；更反直觉的是**更大的评估批量反而让门删掉更多守护**（20 任务批量保住全部保护，40 任务批量在同等成本下丢掉全部六个）。
- **"分数上升就接受"有可量化的代价。** 贪心接受提交 30–42% 的错误编辑与 10–33% 的有害编辑；在有限噪声验证集上取最高分会被"优化者诅咒"向上偏置，正确做法是统计验收门 + 显式弃权。

因此，构建 RSI harness 的第一优先级不是"让它改得更快"，而是"让每次改动都可归因、可回滚，并且让守护的独立性可被验证"。

## 三条理论硬约束

这三条决定了参考架构的形态，而不是可以绕过的实现细节：

| 约束 | 含义 | 出处 |
| --- | --- | --- |
| **门不可能同时可靠且非保守** | 不存在终止性过程既能绝不接受非改进、又绝不漏掉可用改进；唯一可恢复的区间是**有界评估 + 有限提案预算** | [2610.21646](references.md#ref-2610-21646) |
| **安全保持至少是停机问题难度** | 任何有限层监督者都无济于事；恰好幸存的是**运行时监控、按设计限制重写、冻结参考** | [2606.28639](references.md#ref-2606-28639) |
| **安全谓词相对模型不可测** | 语义安全约束是 off-support 的，模型先验与软惩罚杠杆很差；**不变量必须机械强制** | [2608.11243](references.md#ref-2608-11243) |

## 范围与限制

- **这是文献与架构调研，不是实现。** 本仓库没有可运行的 RSI harness 代码；`05` 是蓝图而非交付的软件。
- **未复现任何论文实验。** 文中所有数字均为论文作者自报，除非明确标注。
- **语料有偏。** 1,101 篇论文来自 arXiv 相关性检索，偏向英文、CS/AI、2025–2026；统计只在"检索语料"范围内成立。
- **未做安全审计。** 参考架构的安全机制是设计层面的，不是经过渗透测试的结论。
- **RI（修订改进机制本身）尚无充分实证基础。** 参考架构把 RI 设为默认关闭、最高成熟度阶段；这是谨慎的设计，不是已验证的能力。
