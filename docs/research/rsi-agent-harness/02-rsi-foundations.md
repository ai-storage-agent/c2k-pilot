# 02 · RSI 概念与形式化基础

> 本页给出"递归自我改进"的严格定义、它与其他机器学习范式的区别、失败模式的理论边界，以及这些理论对 harness 设计的约束。
> 主要依据 [2610.35193](references.md#ref-2610-35193) 的操作化定义、[2610.21646](references.md#ref-2610-21646) 的不可能性结果、[2610.38266](references.md#ref-2610-38266) 的成熟度标尺。

## 1. 为什么需要精确定义

"自我改进"被广泛使用，但含义从"重试一次提示词"到"改写自己的训练算法"跨度极大。不做区分会导致两类错误：

- **高估：** 把一个提示词优化循环称为 RSI，从而误判风险与证据要求；
- **低估：** 把真正修订了学习机制的系统的风险当作普通调参。

因此本节采用"功能区分"而非"实现区分"：同一段代码可能同时承担多种角色，关键看它**相对于被评估的任务策略**起什么作用。

## 2. 从机器学习定义出发

[Mitchell (1997)](references.md#ref-2610-35193) 的定义：程序从经验 `E` 中学习任务类 `T` 与性能度量 `P`，若其在 `T` 上按 `P` 度量的表现随 `E` 改善，则称其学习。

泛化需要**归纳偏置** `B`——在符合观测数据的候选策略中做选择的偏好。学习系统记作：

```text
h = A(B, E)
```

- `h`：学到的策略（policy）；
- `B`：支配 `A` 如何学习的归纳偏置；
- `A`：学习过程。

**关键区分（功能性）：**

| 组件 | 含义 | 例子 |
| --- | --- | --- |
| `h` | 任务策略 | "提交补丁前先跑测试" 这条执行指令 |
| `B` | 如何学习/修订策略的偏好 | "挑选修正过的轨迹用于训练" 这条数据选择规则 |
| `U` | 修订 `B` 的机制 | 用失败计数直接改选择规则，还是搜索多个候选规则 |

在 LLM 系统里，`h` 由模型加上提示词、记忆、技能、工具共同实现；`B` 指定策略如何被学习或修订（初始化、训练目标、数据选择规则、优化过程）。

**形式化定义（RSI）：**

> RSI 是一个过程：学习系统从新经验更新其策略、**自主修订其归纳偏置**、并**修订与复用未来偏置更新的机制**，目标是任务表现的持续增益。

写成跨改进循环 `t` 的方程：

```text
h_{t+1}          = A_{B_t}(h_t, E_{t+1})              # 策略更新
(B_{t+1}, U_{t+1}) = U_t(B_t, h_{t+1}, F_{t+1})       # 偏置与更新机制修订
```

其中 `E_{t+1}` 是新经验，`F_{t+1}` 是关于表现与既往改进尝试的反馈。未被接受的组件保持原值。

**RSI 的判别条件：** 修订 `B` 的机制本身被修订（`U_t → U_{t+1}`）并在后续循环中复用。只改 `h` 是改进；改 `B` 是元学习式改进；改 `U` 才是 RSI。

### 2.1 与其他范式的对比

| 范式 | 更新什么 | 更新规则是否可变 |
| --- | --- | --- |
| 常规 ML / RL | `h`（在既定学习规则下） | 否 |
| MAML | 初始化（属 `B`） | 否，元梯度过程固定 |
| AutoML（如 auto-sklearn） | 算法与超参（属 `B`） | 否，搜索过程固定 |
| 学习型优化器 | `B`（优化器本身可被训练） | 外层训练过程相当 `U`；仅当外层过程也被修订并复用才算 RSI |
| Promptbreeder | 任务提示（`h`）+ 变异提示（`B`） | 超变异过程是固定的 `U` |
| Gödel machine | 可自改软件（含证明搜索器），需先证明改动有用 | 理论构造 |
| **RSI** | `h`、`B`，并修订复用 `U` | **是** |

## 3. RSI 过程：S1–S4 与 RI

```text
        E_{t+1}, F_{t+1}
              │
              ▼
   ┌──────────────────────┐
   │ S1 Improvement       │  用 h_t、B_t、新经验与反馈定位限制，
   │    Diagnosis         │  决定改 h、B 还是两者，定义改进目标
   └──────────┬───────────┘
              ▼
   ┌──────────────────────┐
   │ S2 Proposal          │  通过 A_{B_t} 对 h 产生候选，
   │    Generation        │  或通过 U_t 对 B 产生候选（尚未并入系统）
   └──────────┬───────────┘
              ▼
   ┌──────────────────────┐
   │ S3 Proposal          │  按当前评估与验收标准评估候选，
   │    Evaluation        │  检查是否解决限制、是否有跨任务回归
   └──────────┬───────────┘
              ▼
   ┌──────────────────────┐
   │ S4 Update            │  把接受的修订并入后继系统，
   │    Implementation    │  保留 h_{t+1}、B_{t+1}
   └──────────┬───────────┘
              ▼
   ┌──────────────────────┐
   │ RI Recursive         │  把 S1–S4 递归应用于 U_t 自身；
   │    Improvement       │  接受则保留 U_{t+1} 供后续循环复用
   └──────────────────────┘
```

### 3.1 三个变体（编码 agent 示例）

任务目标、外部指定的验收标准与资源预算固定；执行轨迹与修正解提供 `E`，测试结果提供 `F`。

| 变体 | S1 诊断 | S2 提案 | 被改变的是 | S4 保留 |
| --- | --- | --- | --- | --- |
| **策略级** | 反复提交未测试的补丁 | 修改执行提示词 | `h` | 提示词（权重、`B`、`U` 不变） |
| **偏置级** | 同上 | 修改"选择修正轨迹"的规则，提高涉及漏测的修正样本占比 | `B` | 选择规则（架构、优化器、`U` 不变） |
| **递归级** | 同上 | 修改**产生这些选择规则的过程**：从"按失败计数直接调整"改为"在多个候选规则上搜索" | `U` | 修订后的过程，用于后续改 `B` |

**只有第三个变体是 RSI。** 这个区分是评估证据分层的基础：策略级改动只需更新级证据；递归级改动会使此前验证结果可能失效，需要元改进级证据。

### 3.2 改进循环的不同粒度

| 粒度 | 触发 | 成本 | 风险 |
| --- | --- | --- | --- |
| 单次响应内（in-context） | 每次生成 | 极低 | 最低；无持久状态 |
| 任务内（跨步骤） | 任务执行中 | 低 | 局部；随任务结束消失 |
| 任务间（intra-test-time） | 任务流进行中 | 中 | 需要记忆与失效机制 |
| 跨会话（inter-test-time） | 会话边界 | 中-高 | 需要版本化与回滚 |
| 偏置级（`B`） | 改进循环 | 高 | 影响后续所有学习 |
| 元级（`U`） | RI | 最高 | 使先前验证失效；不可逆风险 |

[2507.21046](references.md#ref-2507-21046) 把这一维度形式化为 "what / when / how to evolve"：改什么（模型、记忆、工具、架构）、何时改（intra-test-time / inter-test-time）、如何改（标量奖励、文本反馈、单 agent / 多 agent）。

## 4. 理论边界：验收门的不可能性

这是 RSI 架构最重要的理论约束。[2610.21646](references.md#ref-2610-21646) 的论证结构：

**设定。** 把 agent 建模为程序，用**语义分数**定义"改进"——该分数依赖程序的（可能有界甚至不可计算的）行为。

**两个评估抽象：**

1. **证书器（certifier）：** 批准或拒绝一次更新；
2. **搜索过程（searcher）：** 给定提案生成器，若有改进候选则输出一个。

**结果：** 在全一般设定下，**不存在终止性过程能同时保证**：

- **可靠性（reliability）：** 绝不接受非改进；
- **非保守性（non-conservatism）：** 绝不漏掉可用改进。

自指构造可以迫使任何这样的门或搜索器失败。有限误差的随机门受同样的限制。

**可判定区间：** 该工作同时指出实践中常用的一个可判定设定——**有界评估 + 有限提案预算**——此时穷举模拟得到可行策略。

**对架构的直接约束：**

1. 不能假设门是正确的，只能假设它**未发现反例**；
2. 必须把评估限制在有界区间（有限任务集、有限提案预算）；
3. 必须保留门之外的人为否决与回滚能力；
4. 全自动 RSI 的安全性是**渐近的工程问题**，不是可一劳永逸证明的性质。

### 4.1 单调代理不是单调真值

[2610.21646](references.md#ref-2610-21646) 的另一个结论更具工程杀伤力：**一串被接受的更新可以使有界代理分数每一轮都上升，而真实分数持续下降。** 这解释了为什么"分数上升"不能作为改进的证据，也解释了为什么必须有独立于被优化指标的测量路径。

实用对策（来自 [2609.04665](references.md#ref-2609-04665) 与 [2609.02246](references.md#ref-2609-02246)）：冻结参考分布、秘密 holdout、对"水平差"做变点检测、以及**设计成"满分即为作弊证据"的金丝雀任务**。核心要求是：**优化器不能读取或影响测量路径。**

### 4.2 需要第二个非分数门

[2510.04399](references.md#ref-2510-04399) 给出一个分布无关的结果：自我修改后 PAC 可学习性成立，**当且仅当**策略可达族保持一致容量有界；若可达容量无界，**效用理性的**自我修改就能让可学习任务变为不可学习。其"双门"（Two-Gate）设计 = 验证集改善 + 容量上限，从而恢复标准的 VC 速率保证。

**独立实证支持：** RRSI 的时间退火编辑预算（[2609.24972](references.md#ref-2609-24972)）、ShinkaEvolve 的代码新颖性拒绝采样、RobustSGPO 的权限调度（周期性 1→2→3 优于固定最大值）。

**结论：** 纯"分数有没有上升？"的门在理论上不充分。参考架构的验收门必须包含**容量/搜索空间增长的上界**。

### 4.3 认证不可能，运行时监控可行

[2606.28639](references.md#ref-2606-28639) 把安全性验证推到极限：

- 安全属性沿自我修改轨迹的保持至少是**停机问题难度**；
- 当变换读取代码时，单步就是 Rice 定理的上一级；
- **任何有限层的监督者（tower of supervisors）都无济于事**；
- 任何有限证据的证书器都存在一条轨迹：它在每个阶段都被认证，而属性最终被违反。

**恰好幸存的三件事：**

1. **运行时监控器检测首次违规**（monitor detects the first violation）；
2. **通过设计限制重写**（restricting rewrites by design）；
3. **冻结参考**（frozen reference）使问题保持良定义。

[2606.26057](references.md#ref-2606-26057) 给出具体实现："不可解雇的安全内核"——用 Z3/Kani 验证的执行时强制层，位于 agent 地址空间之外；报告在 1,000 次尝试中**拒绝 704/704 次安全关键的自我修改**，6,240 次授权往返无绕过。

**架构含义：** [04 §8](04-reference-architecture.md) 的治理平面必须是**带外、前置、fail-closed** 的执行层，而不是提示词级的护栏。

### 4.4 硬不变量放 harness，软倾向放模型

[2608.11243](references.md#ref-2608-11243) 给出上述设计选择的理论依据：语义安全谓词是 **off-support** 的——它**相对 σ(model, data) 不可测**，因此在奇异模型中，先验设计与软惩罚加权**杠杆很差**；同一个谓词却能被形式验证**健全地局部认证**。

**结论：** 安全约束属于 harness 的机械强制层；模型可以被训练出良好的倾向，但不承担不变量。

### 4.5 区分"更好的搜索"与"更宽的能力"

[2610.10611](references.md#ref-2610-10611) 提出 **native reach** 与 **closure frontier** 的形式化，并用 **guard-transfer invariance** 防止"表示变化"被算作能力扩张。在 36,864 次配对运行中：

- 反例反馈**减少了验证器调用次数，但没有改变覆盖范围**（纯搜索增益）；
- 一个被启用的权限变更**确实纳入了新的目标**（真实能力扩张）。

**结论：** 大多数头条 RSI 数字（SWE-bench、Polyglot、AIME）按此标准属于**固定已接受任务包络内的搜索增益**。报告必须标注每个数字属于哪一类（见 [04 §7.1](04-reference-architecture.md) 的三层证据）。

### 4.6 组合安全是可行的表述

[2609.33123](references.md#ref-2609-33123) 发现：在**各自安全、且各自保持效用**的更新之间，存在 **43 个成对**与 **18 个不可约的三元**失败；常规验证在此**组合不可行**。其方案是用**类型化超图**只更新"被改变状态的交互邻域"，并驱动**超图引导的运行时监控**。

**架构含义：** 当 harness 每天要跑上千次自我编辑时，超图式的交互感知校验是正确且可扩展的数据结构；逐组件验证不够。

## 5. 已知的失败模式与证据

[2610.35193](references.md#ref-2610-35193) 按 S1–S4 与 RI 梳理了风险与失败证据。综合本调研语料，最有工程价值的是以下几类：

### 5.1 评估侧的失败

| 失败模式 | 机制 | 证据 |
| --- | --- | --- |
| **基准过拟合** | holdout 不足或缺失，agent 走捷径 | [2407.01502](references.md#ref-2407-01502)：许多 agent 基准 holdout 不足甚至没有 |
| **代理信号失效** | "制品累积 + 行为改变 + 指标上升"三个信号都存在，但能力未形成 | [2611.04952](references.md#ref-2611-04952)：Reflexion 的合法性增益、Voyager 的组合覆盖失效、DGM 的只退不进漂移 |
| **重跑不足** | 单次运行的结果被当作稳定增益 | [2610.27610](references.md#ref-2610-27610)：仅 22% 审计 ≥2 次完整循环重跑 |
| **机制对比不匹配** | 比较不同起点或不同预算下的改进机制 | [2610.27610](references.md#ref-2610-27610)：26 项声称改进过程更好的研究中仅 4 项做了匹配对比 |
| **分数与偏好脱节** | 基准增益与人类偏好增益无清晰关联 | RSI Arena：某些 agent 倾向更长回答；一个模型在 StrongREJECT 上有害合规上升 |

### 5.2 治理侧的失败

| 失败模式 | 机制 | 证据 |
| --- | --- | --- |
| **遮罩侵蚀** | 重叠守护下删除单个不可见，门只看任务成功，冗余深度流失 | [2610.38392](references.md#ref-2610-38392)：40 任务批量丢掉全部六个守护；GEPA 最终 harness 中两个在更弱模型下误用凭据 |
| **验证者退化** | 评分器与 agent 共同演化，失去约束后坍缩为恒通过 | [2610.11464](references.md#ref-2610-11464)：坍缩的评分器"训练技能一样好"，下游分数无法证明其有效 |
| **统计检验的假安全** | 显著性检验挡住"靠运气通过"的删除，挡不住"真提升任务成功"的删除 | [2610.38392](references.md#ref-2610-38392) |
| **弱模型暴露** | 强模型掩盖的安全问题在复用更弱模型时显现 | [2610.38392](references.md#ref-2610-38392) |

### 5.3 学习动态的失败

| 失败模式 | 机制 | 证据 |
| --- | --- | --- |
| **稳定性-可塑性权衡** | 全局编辑共享 prompt/workspace，干扰未见过任务并覆盖旧知识 | [2610.25858](references.md#ref-2610-25858)：ReasoningBank、GEPA、Meta-Harness 均如此 |
| **修复-泛化缺口** | 失败衍生经验能修复已失败任务，很少泛化到未见过任务 | [2610.22984](references.md#ref-2610-22984) |
| **技能-策略共同演化陷阱** | 策略能力绑定于共同训练的 skill bank；部署后技能漂移使策略脆弱 | [2610.20845](references.md#ref-2610-20845)：提出 CODA 审计协议与一致性/抗腐蚀指标 |
| **奖励/评分游戏化** | 代理指标可被优化到失去意义 | [2610.11464](references.md#ref-2610-11464) |
| **模型坍塌（训练时）** | 自生成数据循环导致分布收窄 | 自训练文献的已知风险；[2504.13837](references.md#ref-2504-13837) 提示需区分能力扩展与分布内拟合 |

## 6. 成熟度标尺

[2610.38266](references.md#ref-2610-38266) 为"持续能力"与"改进过程"的关系提出 L0–L3 标尺，非常适合作为报告与验收的共同语言：

| 层级 | 名称 | 含义 | 证据要求 |
| --- | --- | --- | --- |
| **L0** | 任务局部适应 | 单任务内调整，无跨任务保留 | 单任务前后对比 |
| **L1** | 持久能力增益 | 经验带来跨任务的持续能力提升 | 跨任务泛化对比，非仅修复已失败任务 |
| **L2** | 继承的过程修订 | 系统修订了数据获取/反馈/学习过程本身 | 过程变更的前后对比；说明继承了什么 |
| **L3** | 经验证的改进器增益 | 修订后的改进器在共享起点、匹配预算下被证明更好 | 相同起始制品、匹配预算、≥2 次重跑 |

该工作同时提出**共享数据与交互式对比**：从相同学习器起点评估参考改进器与修订改进器，从而把"经验的使用"与"改进器本身的变化"分开。这是目前对"机制对比"最可操作的建议。

## 7. 对 harness 设计的约束（由理论反推）

| 理论结论 | 架构约束 |
| --- | --- |
| RSI 需要修订并复用 `U` | 架构必须区分 `h` / `B` / `U` 三层，并给每层不同的证据与审批要求（见 [04 §10 成熟度阶梯](04-reference-architecture.md)） |
| 门不可能同时可靠且非保守 | 门只能作为"必要不充分"条件；人工否决与回滚是**结构性**需要，不是可选保险 |
| 有界评估 + 有限预算时可判定 | 必须显式声明评估任务集与提案预算；预算是一等参数 |
| 修订 `U` 使先前验证可能失效 | RI 通道必须重新验证，不能沿用旧证据；元不变量必须置于 `U` 可达范围之外 |
| 代理信号不足以判定能力形成 | 需要结构化的能力诊断，而不只是指标趋势 |
| 可塑性有稳定性代价 | 更新应局部化；需要显式遗忘/剪枝机制 |

## 8. 与相邻概念的边界

| 概念 | 与 RSI 的关系 |
| --- | --- |
| **元学习** | 修订 `B`，但通常不修订 `U`；是 RSI 的严格子集 |
| **AutoML** | 在固定搜索过程内选择算法/超参；属 `B` 更新 |
| **持续/终身学习** | 关注不遗忘；是 RSI 的必要条件之一（`h` 层面），但不涉及 `B`/`U` |
| **开放式演化** | 关注持续产生新颖性与踏脚石；是 RSI 的搜索机制（如 DGM 的档案） |
| **agentic RL** | 通过交互环境训练 agent 行为；属 `h` 层面的训练时改进 |
| **自我修复 / 重试** | 任务内的临时调整，无持久更新；不属改进 |
| **测试时适应** | 部署时利用测试信号修改状态或预测；属 `h` 层面的推理时改进 |

## 9. 小结

RSI 的严格含义是"修订并复用未来改进机制的能力"。它带来三个不可回避的结论：

1. **风险随层级跃升：** 改 `U` 会使命先前的验证结果失效，因此证据要求也跃升；
2. **自动验收不可完全信任：** 这是可证明的结构性限制，不是工程不足；
3. **证据质量是领域瓶颈：** 当前多数工作报告了增益，却无法证明改进过程本身变强。

参考架构（[04](04-reference-architecture.md)）正是围绕这三条结论组织的。
