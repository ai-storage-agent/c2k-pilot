# 01 · 研究全景：RSI 方向的现状与趋势

> 本页回答"这个领域现在长什么样"。数据来自 2026-11-04 对 arXiv 的 40 组检索 + 经典奠基文献补充（1,101 篇去重论文）与 GitHub 仓库检索（155 个仓库），方法见文末"调研方法与口径"。

## 1. 一句话现状

**"递归自我改进（RSI）"在 2025–2026 年从一个哲学/理论话题，变成了一个有明确制品、明确循环、明确评估争议的工程领域。** 但它同时暴露出严重的证据质量问题：多数工作报告"分数上升"，很少能证明"改进能力本身变强"。

## 2. 领域如何被切分

把语料按"什么在被改进"聚类，可以得到四个互不重叠、但互相依赖的方向。参考架构（[04](04-reference-architecture.md)）正是这四个方向的交叉。

### 2.1 自我修改的 harness / scaffold

**问题：** agent 能否改写自己的代码、提示词、工具和工作流，从而在基准上变强？

| 工作 | 机制 | 关键数字 |
| --- | --- | --- |
| Gödel Agent (2410.04444) | LLM 按高层目标动态修改自身逻辑，无预定义优化算法 | 数学推理与复杂 agent 任务上超过手工 agent |
| Darwin Gödel Machine (2505.22954) | 维护生成 agent 的**档案**，采样后用基础模型生成新版本，形成生长树；用编码基准经验验证每次改动 | SWE-bench 20.0% → 50.0%；Polyglot 14.2% → 30.7% |
| A Self-Improving Coding Agent (2504.15228) | 带基础编码工具的 agent 系统自主编辑自身 | SWE-bench Verified 随机子集 17% → 53% |
| ADAS / Meta Agent Search (2408.08435) | 元 agent 在代码空间迭代编程出更好的 agent，档案持续增长 | 发现的 agent 跨域、跨模型迁移仍优于手写 |
| AFlow (2410.10762) | 把 agentic workflow 的生成自动化（MCTS 式搜索） | 多基准提升且成本更低 |
| HGM-Dual (2610.30042) | 血缘感知的 harness 演化：记录每个祖先改了什么、哪项改善或退化；误差条件下双路径子代生成 | 针对规划任务修正 DGM/HGM 在"改进能力与被改进能力不重合"时的预算浪费 |
| HarnessMM (2610.32813) | 受守护的决策复用 + 对 harness 配置的 RSI | HumanEval：Codex 成功率 90.82%，tokens/task 66.72 → 47.02；DeepSeek Harness：71.43% → 85.71%，96.28 → 11.62 |
| L3M (2610.19591) | 用 Lean 4 写 harness，同时表达不变量与扩展语言；状态全部存于 Git，支持 resume/rewind/fork/compare/merge | 工具的审查层级由"效果可退多远"推导 |

**趋势：** 早期工作（Gödel Agent）强调"任意自我修改"，近期工作（HGM-Dual、HarnessMM、L3M）转向**受约束、可验证、血缘感知**的修改。这是领域在工程化压力下自然收敛的方向。

## 3. 横向趋势

### 3.1 从"能改"到"可验证地改"

2024 年的工作强调自我修改的能力（Gödel Agent）；2026 年的工作强调**约束、血缘、可验证性**（HGM-Dual、L3M、Memento 3 的"仅在接受条件下保留"、RSI-Anything 的"组件与兼容性检查"。这是领域从不成熟到工程化的典型路径。

### 3.2 "harness" 成为一等研究对象

2026 年出现了专门的 harness 综述与研究：
- [2606.20683](references.md#ref-2606-20683) 把执行 harness 分解为**六项耦合的运行时职责**（观测、上下文、控制、动作、状态、验证/治理），并提出四阶段工程范式演进；
- 该综述同时指出自 2026 年初起，harness 已被多份工作独立形式化：六元组、七层 ETCLOVG 分类、code-as-harness 视角；
- 大量 2026 年论文直接以 "harness" 命名（HarnessMM、L3M、DrugHarness、EnactOpt、FreeForm Harness、HGM-Dual、MarkovSim…）。

**统计：** 语料中标题或摘要含 harness/scaffold 的论文：2023 年 3 篇、2024 年 4 篇、2025 年 8 篇、**2026 年 131 篇**。这是一个在一年内爆发的新研究对象。

### 3.3 稳定性-可塑性权衡被实证

[2610.25858](references.md#ref-2610-25858) 在四个漂移任务流上评测 ReasoningBank、GEPA、Meta-Harness，发现：自演化在多数流上提升总体表现，但**更高的可塑性持续以稳定性为代价**——自修改方法对共享 prompt/workspace 做全局编辑，干扰未见过任务并覆盖旧知识；相似度检索把更新局部化，但仍会检索到过时经验。

**架构含义：** 全局重写是危险的默认值；局部化更新 + 显式遗忘/剪枝机制才是可持续的。

### 3.4 评估证据的质量成为独立议题

[2610.27610](references.md#ref-2610-27610) 对 114 项研究做全文编码（其中 90 项自称 RSI），发现：

| 指标 | 比例 |
| --- | --- |
| 报告了超出开发任务的产物评估（宽口径，含部分或未明确分离） | 90% |
| 在**未用于选择**的任务上评估 | 60%（人工编码随机样本中为 45%） |
| 审计了 ≥2 次完整循环重跑 | **22%**（人工样本中 14%） |
| 声称"改进过程更好"的研究（26 项）中，报告了相关对比 | 23/26 |
| 其中在**相同起始制品、匹配预算**下比较早期与后期机制 | **4** |

**结论：** 领域的主要瓶颈不是"提不出改进"，而是"无法证明改进是真的"。

### 3.5 安全与治理从边角变成主题

2026 年出现了以安全为主题的独立工作：
- [2610.38392](references.md#ref-2610-38392) **遮罩侵蚀**：重叠守护下删除单个守护不可见，验收门只看任务成功，冗余深度无声流失；40 任务批量丢掉了全部六个守护；
- [2610.11464](references.md#ref-2610-11464) **验证者退化**：移除锚点守护后评分器坍缩为恒通过，但下游训练效果一样好——分数不能证明验证器有效；
- [2610.21646](references.md#ref-2610-21646) **不可能性结果**：不存在同时可靠且非保守的终止性验收门；
- [2610.35193](references.md#ref-2610-35193) 把可信 RSI 组织为四大主题 × 三个视角。

## 4. 关键争议与未解问题

| 争议 | 立场 A | 立场 B | 证据 |
| --- | --- | --- | --- |
| 增益是否真实 | 自报告基准大幅提升 | 增量多为修复而非泛化；重跑率仅 22% | [2610.27610](references.md#ref-2610-27610)、[2610.22984](references.md#ref-2610-22984)、[2611.04952](references.md#ref-2611-04952) |
| 自演化是否算持续学习 | 聚合表现提升 | 可塑性-稳定性权衡使旧知识被覆盖 | [2610.25858](references.md#ref-2610-25858) |
| 改权重的自训练能否持续 | 零数据路线达到 SOTA | RL 可能未扩展基础能力之外；自我奖励会坍塌 | [2504.13837](references.md#ref-2504-13837)、[2505.03335](references.md#ref-2505-03335) |
| 自动验收门是否可行 | 在可判定有界区间内穷举模拟可行 | 全一般设定下不可能同时可靠且非保守 | [2610.21646](references.md#ref-2610-21646) |
| harness 泛化 vs 专用 | 演化出的 agent 可跨域迁移 | 多数演化针对单一能力，迁移未验证 | [2408.08435](references.md#ref-2408-08435)、[2610.30042](references.md#ref-2610-30042) |

## 5. 对构建 RSI harness 的直接启示

1. **先建评估平面，再建改进引擎。** 领域最常见的失败不是"改不动"，而是"改完不知道是否真的变好"。
2. **把验证器当作需要独立审计的组件。** 下游分数无法证明它有效。
3. **维护约束冗余深度作为一等指标。** 任务成功率上升时，守护可能正在流失。
4. **更新要局部化。** 全局重写共享 prompt 会产生稳定性代价。
5. **档案与血缘不是可选优化。** 它们让诊断有依据、让踏脚石可保留、让审计可追溯。
6. **默认保守。** 拒绝便宜、接受昂贵，是应对不可判定性的工程姿态。

| 项 | 说明 |
| --- | --- |
| 时间 | 2026-11-04（UTC） |
| arXiv 语料 | 40 组检索式，`export.arxiv.org` Atom API，按相关性取回；去重后 **1,101 篇**（含 3 篇 2003 年经典奠基文献：Gödel Machine `cs/0309048`、Schmidhuber `cs/0302012` 等） |
| 检索主题 | recursive self-improvement、self-improving / self-evolving agents、Gödel machine、automated design of agentic systems、meta agent search、self-modifying code、AI scientist、open-ended evolution、continual/lifelong learning、memory & skill libraries、self-reflection、prompt optimization、test-time training、self-play、agentic RL、agent harness/scaffold、context engineering、sandboxing、survey 等 |
| GitHub 语料 | 15 组 `gh search repos` 检索，去重后 **155 个仓库**（见 [07](07-implementation-landscape.md)） |
| 引用口径 | 所有论文引用均通过 arXiv API `id_list` 逐一核验 ID、标题与首次提交日期；未核验的一律不写入正文 |
| 语料时间跨度 | 2003–2026-11；其中 2026 年论文占多数（检索按相关性排序，偏向近期与高相关） |
| 统计口径 | "含 harness/scaffold 的论文"按标题+摘要正则匹配，会包含非架构含义的 scaffold（如分子 scaffold），因此数字用于量级判断而非精确计数 |
| 已知偏差 | arXiv 检索按相关性排序，**不能**当作领域规模的代表性样本；语料偏向英文、CS/AI、且偏向 2025–2026。所有统计均在"检索语料"范围内成立，不外推到整个领域 |
